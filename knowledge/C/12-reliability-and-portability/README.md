# 12 — Reliability and Portability

Language behavior and engineering rules that keep code predictable across optimization levels, compilers, targets, and projects.

## Scope

- undefined behavior
- unspecified behavior
- implementation-defined behavior
- compiler optimization interactions
- diagnostics and warnings
- static analysis
- portability assumptions
- defensive coding
- MISRA C
- SEI CERT C
- BARR-C
- coding-rule rationale

Undefined behavior should also be explained next to the concept that causes it in the owning module.

## Look Here When

Code changes behavior under optimization, differs across compilers or targets, triggers static-analysis findings, or violates a safety/reliability rule.
